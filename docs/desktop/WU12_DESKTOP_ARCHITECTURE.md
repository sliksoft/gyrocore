# WU12 — GyroCore desktop architecture

## Current desktop state (pre-WU12)

| Path | Role |
|------|------|
| `apps/desktop/README.md` | Foundation note only |
| `apps/desktop/blackbox/` | Adapter README for vendored Blackbox Log Viewer |

There was **no** runnable shell, Tauri host, or Core bridge before WU12.
Upstream presentation remains in `third_party/betaflight/` (byte-identical).

## Chosen stack

**Tauri 2 + Vite + React + TypeScript** under `apps/desktop/gyrocore-app/`.

Reasons:

- Matches WU5 “desktop host (Vite/Tauri)” next step
- Real local window, no web-server product architecture
- Sidecar/command pattern fits a Python Core worker
- React matches reusable AeroTuner product patterns (display-only)

## Python Core bridge

```
React UI
  → Tauri command `worker_request`  (or CLI fallback in tests)
  → Python worker  apps/desktop/worker/gyrocore_worker.py
  → core/gyrocore/  (decode → analysis → chirp → autotune → safety → authorize_cli)
```

Protocol: **JSON Lines over stdin/stdout** (one request object, one response object).
No FastAPI / Flask / Redis / DB. No localhost HTTP API in the product path.

Authoritative chain for paste-ready CLI:

`run_safety_pipeline` → `FinalSafeTuneResult` → `authorize_cli` → `ActionableTuneBundle`

The UI never reconstructs actionable CLI.

|-----|---------|

| Blackbox | Vendored viewer host + log metadata |
| Analysis | WU4 evidence display |
| CHIRP | WU7 Bode/coherence when present |
| Tune | WU8 / WU9 / WU10 stages separately |
| Safety | Mechanical / clamps / TOS |
| Compare | Current vs final safe target |
| CLI | Authorized apply/rollback (or preview/denial) |

## Blackbox Viewer

Primary upstream tree: `third_party/betaflight/blackbox-log-viewer/`  
Host package: `apps/desktop/blackbox-host/` (Vite root → vendored tree, **no** edits to third_party).

Integrated via iframe / separate window from the React shell. Tuning authority stays in Python Core.

## AeroTuner UI reuse

Read-only donor. Concepts reused (not SaaS plumbing):

| Donor area | GyroCore use |
|------------|--------------|
| Analyze wizard density / progress ideas | Open + overview status |
| Result / before-after cards | Tune + Compare tables |
| Signals control density | Analysis / CHIRP panels |
| Runs / Compare table idea | Compare page |

Discarded: auth, billing, marketing, Next API routes, Redis, session ownership, cloud upload.

## Demo / fixture mode

Synthetic scenarios generated by the Python worker (clearly labeled). Used when no real CHIRP BBL is available. Not claimed as real flight data.
